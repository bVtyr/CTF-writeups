# Library — Write-up (Express `req.query` array → SQLi)

## Коротко, что произошло
В `GET /actions/login` SQL-запрос собирается строкой через шаблонную подстановку, а “фильтр” на апостроф (`'`) проверяет **не то**, что нужно.  
Из‑за особенностей парсинга query-параметров в Express можно передать `name` **как массив**, обойти фильтр и выполнить `UNION`‑инъекцию.  
Флаг хранится в БД как пароль пользователя `admin`, поэтому при успешной инъекции он возвращается в ответе.

---

## 1) Где лежит флаг
В инициализации БД (файл `src/db.ts`) создаётся таблица `users(name, password)` и затем добавляется пользователь:

- `name = 'admin'`
- `password = FLAG`

То есть флаг — это значение `password` у строки `admin`.

---

## 2) Уязвимый эндпоинт
В `src/index.ts` реализован логин:

- Эндпоинт: `GET /actions/login`
- Берёт `name` и `password` из `req.query`
- Строит SQL строкой примерно так:

```sql
SELECT name FROM users
WHERE name = '<name>' AND password = '<password>'
```

Дальше он делает простой блок-лист:

```ts
if (query.name.includes("'") || query.password.includes("'")) {
  // block
}
```

---

## 3) Почему фильтр обходится
### 3.1. `req.query` может быть массивом
Если один и тот же параметр передать несколько раз, Express (через стандартный парсер) превращает значение в массив.

Пример запроса:
```
/actions/login?name=a&name=b&password=x
```

Тогда:
- `query.name` = `["a", "b"]` (это **Array**, а не строка)

### 3.2. `includes` у массива проверяет элементы, а не подстроки
У массива `.includes("'")` означает: “есть ли элемент массива, **равный** строке `'`”.

Это **не** означает: “содержит ли какая-то строка внутри массива символ `'`”.

Поэтому элемент вида `"...' ..."` не блокируется, потому что это не элемент `"'"` целиком.

### 3.3. При подстановке массива в строку он превращается в `"a,b"`
Когда в шаблонной строке используется `${query.name}`, JavaScript приводит массив к строке через `toString()` → элементы склеиваются запятыми.

В итоге содержимое массива попадает в SQL как одна строка, включая вредоносную часть.

---

## 4) Эксплуатация 
### Цель
Заставить запрос вернуть **значение `password` из таблицы `users`**, то есть флаг.

### Как это делается
1. Передаём параметр `name` **дважды**, чтобы `name` стал массивом.
2. В **первом** `name` размещаем SQL-инъекцию:
   - закрываем строковый литерал
   - добавляем `UNION SELECT password FROM users`
   - комментируем “хвост” запроса (`AND password = ...`)
3. Во **втором** `name` кладём любое безопасное значение (нужно только чтобы получился массив).
4. `password` можно передать любым: он будет закомментирован / не повлияет при корректной инъекции.

### Конкретные payload’ы
> В URL символы должны быть **urlencoded**.

**Вариант A (браузер / curl):**
```text
/actions/login?name=nope%27%20UNION%20SELECT%20password%20FROM%20users--%20&name=x&password=123
```

**Вариант B (через curl, если сервис на localhost:10501):**
```bash
curl 'http://localhost:10501/actions/login?name=nope%27%20UNION%20SELECT%20password%20FROM%20users--%20&name=x&password=123'
```

### Что получается на стороне SQL
Инъекция превращает исходный запрос в эквивалент:

```sql
SELECT name FROM users WHERE name = 'nope'
UNION SELECT password FROM users -- <дальше закомментировано>
```

Первая часть не возвращает строк (пользователя `nope` нет), а `UNION` возвращает `password` каждой строки, включая `admin` → там лежит флаг.
