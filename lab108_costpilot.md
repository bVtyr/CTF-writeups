# Lab 108 - CostPilot - IDOR через устаревший эндпоинт API v1

Приложение: CostPilot (Pilot Financial), трекер расходов для сотрудников.

Баг простой: в проде живут сразу две версии API. Новая, v2, адресует объекты через UUID. Старая, v1, никто не отключил, и она адресует те же самые объекты обычным числовым id без проверки владельца. То есть одну и ту же запись можно достать двумя разными путями, и только один из них защищён.

## Как нашёл

Полазил по самому приложению под обычным юзером (Alex Morgan, Business Analyst), посмотрел список расходов.

<img width="1914" height="994" alt="image" src="https://github.com/user-attachments/assets/c4f5775c-f4c9-4ff3-a956-b2951c596243" />


Попробовал удалить свою запись и посмотрел запрос в Burp:

```
DELETE /api/v2/expenses/9570ccc3-c5e2-4c9f-9978-ddb7ee9e10a0 HTTP/1.1
```

Объект адресуется UUID'ом, его не перебрать. Ответ 200, запись удалилась нормально.

## Эксплуатация

Раз в v2 всё закрыто UUID'ом, проверил, нет ли старой версии того же API. Поменял в пути v2 на v1 и вместо UUID подставил обычный числовой id:

```
GET /api/v1/expenses/3 HTTP/1.1
```

Эндпоинт жив, никакой проверки owner_id на нём нет, он просто отдаёт запись по id, кому бы она ни принадлежала. В ответе чужой расход на $2500 (Consulting Services), и в поле notes лежит флаг с пометкой под NDA.
