# WaF 
**Задача:** получить содержимое `/flag.txt` 

---

## 1) Разведка

Открываем главную страницу и смотрим исходник. В HTML прямо в комментарии оставлен кусок серверной логики:

```py
# def index(filename: str = "index.html"):
#     if ".." in filename or "%" in filename:
#         return "No no not like that :("
```

То есть “WAF” режет всё, где встречается:

- `..` (классический directory traversal)
- `%` (в т.ч. URL-encoding вроде `%2e%2e%2f`)

Поэтому варианты типа:

- `/../flag.txt`
- `/%2e%2e/flag.txt`
- `/..%2f..%2fflag.txt`

не пройдут (в одном месте спалимся на `..`, в другом — на `%`).

---

## 2) Идея обхода

Если напрямую `..` и `%` запрещены, то остаётся искать **альтернативный “переход наверх”**, который:

- не содержит `..` и `%` в строке запроса,
- но на файловой системе ведёт в родительскую папку.

Классический CTF-трюк: **симлинк на `..` с “безопасным” именем**.  
Например, если в веб-каталоге существует симлинк:

```bash
ln -s .. "{.}"
```

то путь `/{.}/` на самом деле указывает на родительскую директорию, хотя в строке нет `..`.

---



## 3) Эксплуатация

Оказалось, что `{.}` можно использовать как “подъём” на уровень вверх.  
Чтобы дойти до корня, нужно сделать это **два раза**, поэтому финальный путь:

- `/{.}/{.}/flag.txt`

В браузере безопаснее передать фигурные скобки в URL-encoded виде:

- `{` → `%7B`
- `}` → `%7D`

Итоговый запрос:

```
"http://45.56.66.96:7789/%7B.%7D/%7B.%7D/flag.txt"
```
